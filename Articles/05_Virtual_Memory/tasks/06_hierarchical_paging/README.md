# Двухуровневая страничная адресация

Виртуальный адрес имеет 12 бит, размер страницы — 256 байт. Младшие 8 бит адреса задают смещение внутри страницы, а старшие 4 бита — номер виртуальной страницы. Номер страницы разделён на две части: старшие 2 бита являются индексом в каталоге таблиц, младшие 2 бита — индексом в таблице второго уровня.

Каталог и таблицы второго уровня заданы следующим образом:

```text
directory = {0, 1, -1, -1}
tables[0] = {5, 3, -1, -1}
tables[1] = {7, -1, -1, -1}
```

Значение `-1` означает, что запись отсутствует. Для каждого виртуального адреса нужно определить физический адрес либо сообщить о страничном отказе.

## Принцип решения

При преобразовании выполняются два доступа к иерархии таблиц. Сначала индекс `directory_index = (VA >> 10) & 3` выбирает таблицу второго уровня в каталоге. Затем индекс `table_index = (VA >> 8) & 3` выбирает запись в этой таблице и даёт номер физического кадра. Если любая из двух записей равна `-1`, возникает страничный отказ.

Смещение `offset = VA & 0xff` не изменяется при преобразовании. Если обе записи присутствуют, физический адрес вычисляется по формуле:

```text
PA = frame * 256 + offset
```

Адрес больше `0xfff` не помещается в 12-битное виртуальное адресное пространство и также приводит к `PAGE_FAULT`.

## Формат ввода

В первой строке задано целое число `q` — количество запросов. В каждой из следующих `q` строк задан один виртуальный адрес `VA` в шестнадцатеричной системе счисления.

## Формат вывода

Для каждого запроса вывести в отдельной строке физический адрес в формате `0x%x` либо `PAGE_FAULT`, если адрес выходит за пределы 12 бит или одна из необходимых записей отсутствует.

## Пример

Ввод:

```text
4
0001
0203
0404
0800
```

Вывод:

```text
0x501
PAGE_FAULT
0x704
PAGE_FAULT
```

Для `0x0001` используются индексы `0` и `0`, кадр `5` и смещение `1`. Для `0x0203` отсутствует запись `tables[0][2]`. Для `0x0404` используются индексы `1` и `0`, кадр `7` и смещение `4`. Для `0x0800` отсутствует запись `directory[2]`.
